# 产品经理 AI 工作台 V1.0 PRD

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 产品经理 AI 工作台 |
| 版本 | V1.0 MVP |
| 文档状态 | 已完成首版梳理，待原型与开发评审 |
| 目标形态 | 单用户、本地优先的桌面工作台 |
| 核心能力 | 需求与 PRD 助手 + 项目资料管理 |

## 2. 产品定位

面向独立产品经理和中小团队产品负责人的 AI 项目工作台，以项目为单位统一管理访谈记录、会议纪要、竞品资料和历史需求，并基于这些资料完成需求分析、PRD、用户故事及验收标准的生成与维护。

产品口号：

> 把散落的项目资料，变成可执行、可追溯的产品需求。

### 2.1 产品价值

- 将产品想法和零散资料集中到同一个项目中；
- 通过 AI 提炼需求，而不是只生成一篇孤立文档；
- 在生成 PRD 前安排用户确认，减少 AI 自行假设；
- 保存项目资料、分析结果、PRD 和对话，方便持续迭代；
- 为熟悉 AI 工具的用户保留模型和执行器选择能力。

### 2.2 与普通 AI 文档工具的区别

V1.0 不把“输入一句话生成 PRD”作为唯一价值，而是提供一条连续工作流：

```text
项目资料沉淀
→ AI 需求分析
→ 用户确认
→ 结构化 PRD
→ 后续继续修改和复用
```

## 3. 目标用户

### 3.1 核心用户

需要独立完成需求整理和 PRD 编写、经常使用 AI、同时管理多个项目的个人产品经理。

### 3.2 用户特征

- 手中经常有想法、会议纪要、访谈记录或业务需求；
- 资料散落在文档、聊天记录和本地文件中；
- 希望 AI 帮助梳理，但仍要自己确认关键结论；
- 可能使用不同模型，并希望在必要时切换；
- 不希望第一版包含复杂的团队权限和审批流程。

### 3.3 V1.0 使用模式

- 单用户；
- 本地优先；
- 不做组织、成员、角色和复杂权限；
- 不以企业采购和多人协作为首版目标。

## 4. 核心使用场景

V1.0 同时允许三种入口创建项目：

1. **从产品想法开始**：用户输入一段想法，由 AI 帮助补全需求；
2. **从现有资料开始**：用户导入访谈、会议或竞品资料，由 AI 提炼需求；
3. **从业务需求开始**：用户粘贴业务方提出的需求，由 AI 进行分析和结构化。

第一版重点优化：

> 从产品想法或现有资料出发，经过 AI 分析和用户确认，生成结构化 PRD。

## 5. V1.0 核心业务闭环

```text
用户进入工作台
→ 创建产品项目
→ 选择开始方式：产品想法 / 导入资料 / 业务需求
→ 系统默认选择“需求与 PRD 助手”
→ 系统使用项目默认模型和执行方式
→ 用户输入内容或导入资料
→ AI 分析资料并输出结构化需求和待确认问题
→ 用户修改并确认关键需求
→ AI 根据已确认内容生成结构化 PRD
→ 用户编辑并保存 PRD
→ 按需生成用户故事和验收标准
→ 系统保存项目资料、分析结果、对话和 PRD
→ 用户下次打开项目继续工作
```

### 5.1 闭环中的人工确认点

- AI 完成需求分析后，用户需要检查和修改；
- 用户确认关键需求后，才能生成正式 PRD；
- AI 生成的用户故事和验收标准可以继续编辑；
- 系统不得把 AI 推测自动标记为用户已确认事实。

## 7. 页面与功能需求

### 7.1 工作台首页

#### 目标

让用户快速开始新工作或继续最近的项目。

#### V1.0 功能

- 创建项目；
- 查看并打开最近项目；
- 查看最近对话；
- 查看正在运行的任务；
- 快捷入口：从产品想法开始；
- 快捷入口：导入现有资料。

### 7.2 项目列表

#### V1.0 功能

- 创建项目；
- 按项目名称搜索；
- 打开项目；
- 置顶项目；
- 删除项目，删除前二次确认；
- 显示项目名称和最后更新时间。

#### 暂不实现

- 项目归档；
- 多层分类；
- 批量操作；
- 团队项目与权限。

### 7.3 项目工作区

#### 顶部信息

- 项目名称；
- 当前助手；
- 当前模型；
- “更多设置”入口。

项目顶部不显示“当前阶段”，避免增加不必要的流程管理负担。

#### 内部页面

- 项目概览；
- 项目资料；
- 需求分析；
- PRD。

### 7.4 项目资料

#### 目标

保存本项目中 AI 分析时可以使用的原始资料。

#### V1.0 功能

- 上传文件；
- 粘贴文本；
- 添加本地文件夹；
- 查看资料列表；
- 预览资料内容；
- 显示解析成功或失败；
- 删除资料。

#### 暂不实现

- 复杂标签体系；
- 高级全文搜索；
- 资料关系图；
- 复杂版本管理；
- 批量资料处理；
- 自定义解析参数。

### 7.5 需求分析

#### 目标

将用户输入和项目资料整理成可确认的需求结论，为生成 PRD 做准备。

#### 输出内容

- 产品目标；
- 目标用户；
- 用户场景；
- 用户痛点；
- 核心需求；
- MVP 范围；
- 待确认问题。

#### 用户操作

- 触发 AI 分析；
- 编辑分析结果；
- 删除不正确的内容；
- 确认分析结果；
- 查看本次分析使用了多少份项目资料。

#### 暂不实现

- 逐条接受或拒绝；
- 事实与推测的复杂标签；
- 需求冲突管理；
- 优先级计算模型；
- 来源关系图；
- 分析版本对比。

### 7.6 PRD 工作区

#### 目标

根据用户已确认的需求生成并维护结构化 PRD。

#### 默认 PRD 结构

1. 产品背景；
2. 产品目标；
3. 目标用户；
4. 核心场景；
5. 功能范围；
6. 核心业务流程；
7. 功能需求；
8. 非功能要求；
9. 用户故事与验收标准；
10. 暂不实现范围；
11. 待确认问题。

#### V1.0 功能

- 根据已确认需求生成 PRD；
- 在线编辑 PRD；
- 自动保存，并支持手动保存；
- 单独重新生成某一章节；
- 导出 Markdown 文件；
- 将用户故事和验收标准作为 PRD 中的可选章节生成。

#### 暂不实现

- 独立的用户故事页面；
- 三栏复杂编辑器；
- 文档版本对比；
- 来源关系侧栏；
- 评论与审批；
- Word、PDF 等多格式导出。

### 7.7 新会话

#### 目标

允许用户进行临时问答，或围绕指定项目继续处理资料和需求。

#### V1.0 功能

- 新建对话；
- 选择关联项目；
- 选择助手；
- 选择模型；
- 输入文字；
- 上传文件；
- 查看 AI 回答；
- 停止生成；
- 重新生成。

关联项目后，对话默认可以使用该项目的资料。

#### 暂不实现

- 对话分支；
- 多结果并排比较；
- 对话标签；
- 高级模型参数；
- 多 Agent 协作编排。

### 7.8 任务中心

#### V1.0 功能

- 查看正在执行的 AI 任务；
- 查看已完成和失败的任务；
- 显示任务所属项目；
- 停止正在执行的任务；
- 对失败任务进行重试。

任务中心仅承担运行状态查看，不做复杂的项目进度管理。

### 7.9 设置

#### V1.0 功能

- 配置模型服务；
- 测试模型连接；
- 设置默认模型；
- 查看 Codex/Pi 是否可用；
- 设置默认执行方式；
- 设置本地数据保存位置；

## 8. 助手、执行器与模型规则

### 8.1 三个概念

| 层级 | 用户看到的例子 | 作用 |
|---|---|---|
| 助手 | 需求与 PRD 助手、产品经理开发助手、通用助手 | 决定当前要完成什么工作 |
| 执行器 | 自动、Codex CLI、Pi | 决定任务由哪套 Agent 能力执行 |
| 模型 | GPT、Claude、Gemini、DeepSeek 等 | 决定使用哪个大模型 |

### 8.2 V1.0 交互原则

- “助手”是用户的主要选择，直接显示；
- “模型”可以显示，但默认使用项目默认模型；
- “执行器”放在“更多设置”中，默认选择“自动”；
- 普通 PRD 生成不要求用户理解 Codex 或 Pi；
- 用户主动切换后，系统记住该项目的选择；
- 执行器不可用时，应提示原因，并允许改回“自动”或其他可用方式；
- Codex 更适合代码仓库和开发类任务，不作为普通 PRD 生成的强制依赖。

### 8.3 默认规则

```text
创建项目
→ 默认助手：需求与 PRD 助手
→ 默认执行器：自动
→ 默认模型：用户在设置中配置的默认模型
```

## 9. 核心数据对象

V1.0 只保留完成闭环所需的数据：

| 对象 | 主要内容 |
|---|---|
| 项目 | 名称、创建时间、更新时间、默认助手、默认模型、默认执行器 |
| 项目资料 | 文件或文本、解析状态、所属项目 |
| 需求分析 | 分析内容、确认状态、更新时间 |
| PRD | 标题、正文、保存时间、所属项目 |
| 对话 | 消息内容、关联项目、使用的助手和模型 |
| 任务 | 类型、运行状态、失败原因、所属项目 |

## 10. V1.0 验收标准

### 10.1 主流程验收

```text
Given：用户已经配置至少一个可用模型
When：用户创建项目，输入产品想法或导入一份资料，完成需求分析并确认
Then：系统能够生成一份结构化 PRD，用户可以编辑、保存并再次打开
```

### 10.2 项目与资料

- 用户可以创建、搜索、打开、置顶和删除项目；
- 用户可以上传资料或粘贴文本；
- 资料解析成功或失败时有明确状态；
- 解析失败不会删除原文件，用户可以重试；
- 关闭并重新打开应用后，项目和资料仍然存在。

### 10.3 需求分析

- AI 能基于用户输入和已选择的项目资料生成结构化分析；
- 分析至少包含产品目标、目标用户、核心需求、MVP 范围和待确认问题；
- 用户可以修改或删除分析内容；
- 未确认分析结果时，系统应提醒用户确认后再生成正式 PRD；
- AI 生成失败时保留用户输入，并允许重试。

### 10.4 PRD

- 系统可以根据已确认需求生成结构化 PRD；
- 用户可以编辑并保存 PRD；
- 用户可以重新生成单个章节，而不覆盖整篇文档；
- 用户可以选择生成用户故事和验收标准章节；
- 用户可以导出 Markdown；
- 重新进入项目后可以继续编辑上次保存的 PRD。

### 10.5 模型与执行器

- 用户可以在项目中查看和切换模型；
- Codex/Pi/自动执行方式可以在“更多设置”中选择；
- 用户不手动选择执行器，也能完成需求分析和 PRD 生成；
- 当前模型或执行器不可用时，系统给出可理解的错误和切换入口；
- 重复点击生成按钮不会创建多个相同任务。

### 10.6 基础状态

主要页面需要具备：

- 空数据状态；
- 加载状态；
- AI 生成中状态；
- 成功状态；
- 失败与重试状态；
- 停止生成状态；
- 关闭页面后再次进入的数据恢复。

## 11. V1.0 范围边界

### 11.1 本期必须完成

- 项目资料导入和查看；

- 用户修改与确认；

- 复杂需求优先级模型；
- 资料关系图和知识图谱；
- 独立用户故事管理页面；
- PRD 版本对比；
- Word/PDF 多格式导出；
- 企业系统深度集成；
- 完整研发项目管理；
- 移动端。

## 12. MVP 成功判断

V1.0 达标的核心不是页面数量，而是用户能够独立完成以下过程：

> 创建一个项目，放入想法或资料，通过 AI 得到可修改的需求分析，确认后生成并保存一份可继续维护的 PRD。

只要这条主链路稳定、清楚、可恢复，V1.0 就具备进入原型和开发验证的条件。
