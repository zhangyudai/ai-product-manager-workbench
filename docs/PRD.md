# 产品经理 AI 工作台 PRD

> 版本：V0.1  
> 状态：产品初稿，待评审  
> 日期：2026-10-02  
> 产品形态：桌面端 AI 工作台  
> 目标阶段：MVP

## 1. 产品概述

### 1.1 一句话定位

面向产品经理的 AI 桌面工作台，将需求资料、AI 对话、PRD、任务拆解、项目文件和验收记录集中在一个项目空间内，帮助产品经理从想法走到可交付需求。

### 1.2 产品背景

产品经理的日常工作分散在聊天工具、文档、网盘、项目管理系统和多个 AI 产品中，常见问题包括：

- 需求资料散落，难以形成统一上下文；
- AI 讨论结果难以沉淀到具体项目；
- PRD、用户故事、开发任务和验收标准之间存在重复整理；
- 不同模型的输出缺少统一比较和留存；
- 项目决策、版本和交付记录容易丢失；
- AI 能生成内容，但缺少确认、失败恢复和结果追踪等完整工作流。

本产品以“项目”为核心容器，通过 AI Agent 串联需求分析、PRD 生成、任务拆解和验收准备。

## 2. 产品目标

### 2.1 MVP 核心闭环

```text
创建产品项目
→ 导入需求材料
→ AI 提取用户、场景、痛点和需求
→ 产品经理确认或修改
→ 生成结构化 PRD
→ 拆分用户故事和验收标准
→ 保存为项目成果
→ 关闭应用后能够恢复
```

### 2.2 业务目标

- 降低产品经理整理需求和编写 PRD 的重复劳动；
- 让 AI 输出与具体项目、资料和决策建立关联；
- 让需求从输入到验收具备可追踪的结构化记录；
- 验证用户是否愿意持续通过项目工作台管理 AI 协作成果。

### 2.3 用户完成闭环后获得

1. 一份结构化需求分析；
2. 一份可编辑的 PRD；
3. 一组用户故事；
4. 每条用户故事对应的验收标准；
5. 可恢复、可追踪的项目记录。

### 2.4 MVP 非目标

- 替代 Jira、Linear、飞书项目等完整项目管理平台；
- 自动向生产环境发布或部署代码；
- 未经确认发送邮件、修改日程或写入第三方系统；
- 建设完整企业组织、计费和商业化体系；
- 支持所有文档格式、模型和办公平台；
- 建设多人实时协同编辑能力。

## 3. 目标用户

### 3.1 核心用户

第一阶段面向独立产品经理、创业团队产品负责人和 AI 产品经理。

典型特征：

- 同时处理多个产品想法或需求；
- 经常使用 AI 辅助调研、分析和文档编写；
- 能判断 AI 输出质量，但不希望维护复杂技术配置；
- 主要使用 Windows 或 macOS 桌面设备；
- 需要将 AI 结果沉淀到真实项目中。

### 3.2 次要用户

- 设计师：查看需求背景、流程和交互要求；
- 开发人员：查看范围、用户故事和验收标准；
- 测试人员：根据验收标准准备测试；
- 项目负责人：了解阶段、风险和待确认事项。

### 3.3 MVP 权限

| 角色 | 能力 |
|---|---|
| 项目所有者 | 创建项目、上传资料、调用 AI、编辑和删除项目成果 |
| 项目成员（预留） | 查看项目资料和成果，编辑权限后续确定 |
| 本地管理员 | 配置模型服务、应用设置和数据目录 |

MVP 优先完成单用户本地使用，多人协作和企业权限放入后续版本。

## 4. 核心场景

### 4.1 需求梳理

用户输入产品想法，或上传访谈、会议纪要、竞品材料。AI 提取目标用户、使用场景、用户痛点、用户目标、候选需求、约束和待确认问题。结果必须由用户确认，不能直接当作最终事实。

### 4.2 PRD 生成

用户确认需求分析后，AI 生成结构化 PRD，至少包含：背景、目标、用户与场景、范围与非范围、核心流程、功能需求、异常状态、数据与权限、验收标准、风险及待确认事项。

### 4.3 用户故事与验收标准

用户可从 PRD 生成用户故事。每条故事包含角色、目标、价值、前置条件、正常流程、异常流程、Given/When/Then 验收标准、优先级和所属版本。

### 4.4 项目资料协作

用户将本地文件或文件夹加入项目，让 AI 在明确授权范围内分析。系统必须显示本次任务使用了哪些资料，避免用户误以为 AI 已读取整个电脑。

### 4.5 模型对比

用户选择 2～4 个已配置模型，以相同提示词和材料独立对比输出、状态和耗时，并保存结果。模型对比是辅助工具，不作为 MVP 主业务入口。

## 5. 信息架构

### 5.1 一级导航

| 页面 | 说明 | MVP |
|---|---|---|
| 工作台首页 | 最近项目、待处理事项、快捷创建 | 是 |
| 项目 | 项目列表与项目工作区 | 是 |
| AI 对话 | 通用对话和项目内对话 | 是 |
| 模型对比台 | 多模型并行比较 | 是 |
| 任务中心 | AI 任务状态与历史 | 是 |
| 助手 | 管理专用 Agent | 复用现有能力 |
| 团队 | 多 Agent 或多人协作 | 后续 |
| 定时任务 | 自动化任务 | 后续 |
| 设置 | 模型、数据、显示和应用设置 | 是 |

### 5.2 项目工作区

- 项目概览；
- 项目资料；
- 需求分析；
- PRD；
- 用户故事；
- 验收清单；
- AI 对话记录；
- 项目成果；
- 项目设置。

## 6. 核心流程

### 6.1 首次使用

1. 用户打开应用；
2. 系统检查是否已有可用模型；
3. 未配置时引导用户完成模型设置和连接测试；
4. 配置成功后进入工作台；
5. 用户创建第一个项目。

### 6.2 从想法生成 PRD

1. 用户点击“创建项目”；
2. 输入项目名称和一句话描述；
3. 可选上传资料或项目文件夹；
4. 点击“开始需求梳理”；
5. 系统创建任务并展示真实状态；
6. AI 输出结构化需求分析和待确认问题；
7. 用户修改并确认；
8. 用户点击“生成 PRD”；
9. 系统基于已确认内容生成 PRD；
10. 用户编辑并保存；
11. 系统保存版本和来源信息；
12. 用户继续生成用户故事和验收标准。

### 6.3 中断与恢复

- 页面关闭或连接中断不代表任务失败；
- 再次进入项目时，根据任务 ID 查询真实状态；
- 已完成任务展示结果，运行中的任务继续展示进度；
- 失败任务保留原始输入和已生成内容；
- 重试不得重复创建项目或覆盖已确认内容。

## 7. 功能需求

### FR-01 项目管理

- 创建、重命名、归档和删除项目；
- 查看最近访问时间和当前阶段；
- 从首页恢复最近项目；
- 搜索项目；
- 删除前展示影响并二次确认；
- 关闭应用后项目仍然存在。

### FR-02 项目资料

- 添加文件或本地项目文件夹；
- 查看已授权资料及解析状态；
- 移除资料；
- 发起任务前选择本次使用的资料范围；
- MVP 暂定支持 TXT、Markdown、PDF、DOCX、CSV 和 JSON。

文件大小和解析失败策略在技术适配阶段确定。

### FR-03 AI 需求分析

AI 输出必须是可编辑结构，至少包含用户、场景、痛点、目标、需求、假设、约束和待确认事项。用户可以逐项编辑、接受或删除，并明确点击“确认分析结果”。

### FR-04 PRD 管理

- 从已确认分析生成 PRD；
- 编辑并手动保存；
- 查看最近保存时间；
- 查看和恢复历史版本；
- 导出 Markdown；
- 后续支持导出 Word 和 PDF；
- 未经确认不得覆盖人工修改内容。

### FR-05 用户故事

- 从 PRD 生成用户故事；
- 调整优先级和所属版本；
- 编辑验收标准；
- 标记为待评审、已确认或已废弃；
- 导出 Markdown 或 CSV。

### FR-06 AI 任务中心

| 状态 | 用户含义 |
|---|---|
| idle | 尚未开始 |
| submitting | 正在提交 |
| queued | 已受理，等待执行 |
| running | 正在执行 |
| streaming | 正在返回内容 |
| waiting_user | 等待确认或补充 |
| succeeded | 已完成 |
| partially_succeeded | 部分完成 |
| failed | 执行失败 |
| cancelled | 已取消 |
| disconnected | 连接中断，任务未必停止 |
| stale | 状态可能过期，正在刷新 |

用户能够查看、停止、重试任务并返回对应项目。

### FR-07 AI 对话

- 支持普通对话和项目内对话；
- 项目内对话展示当前项目和引用资料；
- 支持流式输出、停止和重新生成；
- 刷新后恢复会话；
- AI 输出可保存为项目成果；
- 不展示内部系统提示词和敏感日志。

### FR-08 模型对比台

- 选择 2～4 个模型；
- 使用统一提示词和材料；
- 独立流式展示；
- 单独停止或重新生成；
- 复制结果并保存记录；
- 展示模型来源、状态和耗时；
- 明确提示重试会产生新的模型调用费用。

### FR-09 设置

- 模型服务配置和连接测试；
- 默认模型；
- 数据存储位置；
- 主题和语言；
- 应用版本；
- 数据导出与清理；
- 诊断信息。

密钥只能交给本地后端或安全存储，不得出现在页面日志或导出文件中。

## 8. Agent 行为规则

### 8.1 可直接执行

- 分析用户明确选择的资料；
- 生成需求、PRD和用户故事草稿；
- 总结、改写和分类用户内容；
- 保存到当前项目草稿区。

### 8.2 必须由用户确认

- 覆盖人工编辑后的 PRD；
- 删除项目、资料或成果；
- 对外发送邮件或消息；
- 创建或修改日程；
- 写入外部项目管理系统；
- 批量修改数据；
- 产生明显费用的批量调用；
- 访问项目之外的本地文件；
- 发布或分享项目内容。

### 8.3 输出标识

AI 应区分资料支持的事实、AI 推断、产品假设和待用户确认事项。引用资料时应尽可能显示文件来源。

## 9. 数据、隐私与安全

- MVP 默认本地优先存储；
- 用户选择资料后，才允许向模型发送必要内容；
- 用户能够看到当前任务使用的资料范围；
- 支持清理项目、对话和模型配置；
- 日志不默认记录完整提示词、项目正文、密钥和私人文件；
- 前端隐藏按钮不等于权限控制；
- 外部系统操作由后端再次校验权限；
- 高风险操作需要确认和操作记录；
- 多人版本必须实现项目级数据隔离。

## 10. 非功能要求

### 10.1 可用性

- 首次用户应能在 10 分钟内配置模型并创建项目；
- 所有核心状态说明“当前发生什么、用户需要做什么、下一步是什么”；
- 任务失败不得丢失用户输入；
- 重复点击不得创建重复任务；
- 加载状态不能显示成空数据；
- 断线不能直接显示成任务失败。

### 10.2 性能

- 本地页面切换在 1 秒内给出反馈；
- 提交任务后 500 毫秒内显示已受理；
- 流式内容到达后持续展示；
- 大型资料解析展示独立进度，不阻塞整个应用。

模型响应时间不计入本地页面性能，但必须持续反馈状态。

### 10.3 兼容性与稳定性

- MVP 优先支持 Windows 11，后续支持 macOS；
- 支持 1280×720 及以上桌面窗口；
- 窄窗口下核心流程仍可操作；
- 任务状态以后端为最终事实来源；
- 异常退出后可以恢复项目和已保存成果；
- 网络恢复后重新查询任务，避免重复创建；
- 未知状态必须安全兜底并记录诊断信息。

## 11. 成功指标

| 指标 | 定义 | 暂定目标 |
|---|---|---|
| 首次闭环完成率 | 新用户完成“项目→分析→PRD保存” | ≥60% |
| PRD 有效保存率 | 生成后被编辑并保存的 PRD 比例 | ≥50% |
| 任务成功率 | 非用户取消任务的成功比例 | ≥90% |
| 恢复成功率 | 刷新或重启后恢复任务/结果 | ≥95% |
| 周复用率 | 一周内再次创建或继续项目 | ≥30% |
| 平均节省时间 | 用户自评相对原流程节省时间 | ≥30% |

目标值应在首轮内测后根据真实数据调整。

## 12. MVP 验收标准

Given 用户已配置一个可用模型  
When 用户创建项目、输入想法并上传一份需求材料  
Then：

1. 系统成功创建项目；
2. AI 输出结构化需求分析；
3. 用户能够编辑并确认分析结果；
4. 系统基于确认内容生成 PRD；
5. 用户能够编辑和保存 PRD；
6. 系统从 PRD 生成至少一条用户故事及验收标准；
7. 关闭并重新打开应用后，项目和成果仍然存在；
8. 失败或断网后，原始输入和已保存结果不丢失；
9. 重试不会重复创建项目；
10. 全链路使用真实后端和真实模型，不以 Mock 数据代替。

交付前还必须通过格式检查、Lint、类型检查、相关单元测试、生产构建和至少一条核心流程 E2E，并列出未完成项和已知问题。

## 14. 技术适配约束

参考项目采用 Electron 桌面端、React 前端与 Rust 后端。MVP 应优先复用现有的会话、模型配置、项目文件夹、助手、模型对比、流式通信、本地存储以及测试基础设施。

不为套用通用 Web 技术栈而强制迁移到 Next.js。编码前需要补充《技术适配声明》，明确复用与改造模块、业务数据模型、Agent 状态映射、文件解析方案、前后端接口、测试和打包方案。

## 15. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 功能入口过多 | 用户不知道从哪里开始 | 首页突出“创建项目”和主流程 |
| AI 输出不稳定 | PRD 质量不可预测 | 结构化输出、模板、确认和重试 |
| 资料超过上下文 | 遗漏关键信息 | 分段解析、摘要和引用范围提示 |
| 模型配置复杂 | 新用户无法开始 | 配置引导和连接测试 |
| 产品定位不突出 | 变成通用 AI 工具 | 以项目工作区重组信息架构 |
| 桌面端打包复杂 | 发布周期变长 | 尽早建立打包和冒烟测试 |
| 隐私资料上传模型 | 用户不敢使用 | 明确数据路径、本地优先和发送范围 |
| 长任务断线 | 用户误认为结果丢失 | 任务 ID、后端状态和恢复机制 |

## 16. 待产品确认事项

1. 第一版优先服务独立产品经理，还是企业内部产品团队？
2. MVP 是否只做单用户本地版？
3. 是否确定沿用现有 AionUi / AionCore 代码底座？
4. PDF 和 Word 是否必须在首版完成解析？
5. PRD 首版使用 Markdown 编辑器还是结构化表单？
6. 是否需要首版导出 Word/PDF？
7. 模型费用由用户自行配置 API Key，还是由平台提供？
8. 模型对比台是否保留为一级导航？
9. 首发平台只做 Windows，还是同时支持 macOS？
10. 产品正式名称和品牌视觉是什么？

## 17. 本版假设

在产品确认前，本 PRD 暂按以下假设推进：

- 产品为桌面端；
- MVP 面向个人产品经理；
- 数据本地优先；
- 用户自行配置模型服务；
- 复用 AionUi / AionCore；
- 主闭环为“项目→需求分析→PRD→用户故事→验收标准”；
- 外部办公系统写入不进入 MVP；
- 高风险操作始终需要用户确认。

以上假设发生变化时，应同步更新范围、版本计划和验收标准。
