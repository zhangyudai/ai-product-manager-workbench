# 产品经理 AI 工作台 V1.1 设计说明

> 状态：已确认原型版本
>
> 日期：2026-10-07
>
> 产品依据：[PRD.md](./PRD.md)
> 可点击原型：[product-manager-workbench-v1.1.html](./prototypes/product-manager-workbench-v1.1.html)

## 1. 文档目的

本文统一记录产品经理 AI 工作台 V1.1 的信息架构、页面职责、核心流程、状态与恢复规则、视觉方向和前端验收标准，作为后续 AionUi 正式前端实现的设计依据。

PRD 与本文冲突时，以 `docs/PRD.md` 为准。HTML 文件是用于评审的可点击原型，不代表生产功能已经完成。

## 2. 产品与设计目标

产品面向独立产品经理和中小团队产品负责人，用一个本地优先桌面工作台统一管理产品想法、业务需求、访谈、会议纪要、竞品资料、需求分析、对话与 PRD。

设计目标：

- 用户能快速开始正式产品工作，也能随时发起临时问答；
- 项目、会话和任务的入口清晰，不依赖隐藏操作；
- AI 先生成可编辑草稿，用户确认后再生成正式 PRD；
- 用户知道当前项目、助手、模型和本次使用的资料；
- 中断、失败、刷新或重新打开应用后，已保存工作可以恢复；
- 界面适合高频、信息密集的生产力工作。

## 3. 设计原则

### 3.1 行为原则

1. 明确入口：工作台首页必须有可见一级导航，不把品牌点击作为唯一返回方式。
2. 明确创建：新建会话是高可见创建动作，不与正式项目流程混为一谈。
3. 人工确认：AI 分析是草稿，用户确认关键需求后才能生成正式 PRD。
4. 上下文透明：发送前显示关联项目、助手、模型和可使用的资料范围。
5. 可恢复：任务失败或应用中断时保留输入、已生成内容和真实任务状态。
6. 本地优先：项目数据默认保存在本机，密钥不得明文展示或写入日志。

### 3.2 视觉参数

本项目专用设计参数：

- 创新程度：`4/10`，有辨识度但不采用实验性艺术布局；
- 动效程度：`2/10`，仅通过克制动效表达状态和反馈；
- 信息密度：`8/10`，适合桌面生产力工具和重复操作。

视觉优先级为清晰、稳定、可扫描和高效。避免营销页面式大面积装饰、电影化动效和与任务竞争注意力的视觉元素。

## 4. 信息架构

```text
产品名称 / PM 标识（产品识别；辅助返回工作台）
├── 工作台
├── 新建会话（主要创建动作；Ctrl+N）
├── 项目
├── 任务
└── 设置

最近项目
├── AI 产品工作台
└── 海外定制销售工具

最近对话
├── 梳理产品定价方案
│   └── 未关联项目 · 10 分钟前
└── 修改需求确认流程
    └── AI 产品工作台 · 昨天
```

### 4.1 导航职责

| 入口 | 职责 | 关键规则 |
|---|---|---|
| 工作台 | 返回首页、开始或继续产品工作 | 明确显示为一级导航并具有选中状态 |
| 新建会话 | 发起临时问答或关联项目的对话 | 默认不关联项目；使用轻度高亮样式；支持 `Ctrl+N` |
| 项目 | 查看、搜索、创建和打开项目 | 项目是资料、分析和 PRD 的主要容器 |
| 任务 | 查看运行中、完成和失败的后台任务 | AionCore 返回状态是最终事实来源 |
| 设置 | 配置模型、执行器、本地存储、主题和语言 | 固定在侧栏底部 |

点击左上角品牌与点击“工作台”效果一致，但品牌只作为冗余快捷方式，不承担唯一导航职责。

### 4.2 最近项目与最近对话

- 两者是同级分组，不混排；
- 每组在侧栏展示最近 3～5 项；
- 最近项目显示项目名称和更新时间；
- 最近对话显示会话标题、所属项目或“未关联项目”和更新时间；
- 点击最近对话恢复原消息、项目关联、助手和模型，不创建重复会话；
- “未关联项目”表示会话没有项目上下文；“归档”保留给未来隐藏或归档功能。

## 5. 全局桌面壳层

### 5.1 左侧栏

- 顶部显示 PM 标识、产品名称和版本；
- 一级导航依次为工作台、新建会话、项目和任务；
- 当前页面只有一个一级入口显示选中状态；
- 新建会话使用带加号的轻度高亮按钮；
- 最近项目与最近对话位于一级导航下方；
- 设置固定在底部；
- 不显示团队、成员、权限和“当前阶段”。

### 5.2 页面顶部

- 工作台显示本地服务状态和帮助入口；
- 项目工作区显示项目名称、当前助手和当前模型；
- 执行器不在主界面突出，收入“更多设置”；
- 成功状态必须来自真实保存或任务完成，不由前端动画自行判定。

### 5.3 窗口与键盘

- 核心入口、按钮、表单、输入区和编辑区可通过键盘到达；
- `Ctrl+N` 创建新的未关联项目会话，并将焦点放入输入框；
- 窗口变窄时允许侧栏收窄，但主要操作仍需可达；
- 不允许出现无法恢复的遮挡、截断或水平滚动；
- 尊重减少动态效果设置。

## 6. 页面设计

### 6.1 工作台首页

目标：让用户快速开始正式产品工作、继续最近工作或直接输入需求。

主要内容：

- 三个正式工作入口：从产品想法开始、导入现有资料、分析业务需求；
- 主要输入框；
- 当前助手和模型；
- 更多设置；
- 当前项目和本次可使用的资料数量；
- 最近项目和最近对话的完整记录。

首页三个卡片启动正式项目流程，不等同于临时新建会话。

### 6.2 新建会话

目标：进行临时问答，或在选择项目后继续处理该项目的资料和需求。

输入区包含：

- 文字输入；
- 文件上传；
- 关联项目；
- 助手选择；
- 模型选择；
- 更多设置中的执行器；
- 发送或停止按钮。

默认规则：

- 默认助手为“需求与 PRD 助手”；
- 助手可选“需求与 PRD 助手”“产品经理开发助手”“通用助手”；
- 未关联项目时使用全局默认模型；
- 关联项目后使用项目默认模型；
- 模型选择器显示“项目默认”或“全局默认”的来源；
- 执行器默认“自动”，Codex CLI 和 Pi 收入“更多设置”；
- 关联项目后显示本次可使用的资料数量；
- 用户主动切换助手、模型或执行器后，项目记住该选择。

会话发送第一条有效消息后生成标题并进入最近对话。未关联项目会话显示“未关联项目 · 更新时间”。

### 6.3 项目列表

- 创建项目；
- 按名称搜索；
- 打开和置顶项目；
- 显示资料数量和更新时间；
- 删除前二次确认并明确影响范围；
- V1.0 不做项目归档、团队项目和权限管理。

### 6.4 项目工作区

项目顶部显示项目名称、保存时间、当前助手和当前模型，不显示“当前阶段”。

项目内包含：

1. 概览：查看资料、需求分析和 PRD 的最新状态；
2. 资料：上传、粘贴、查看和删除项目资料；
3. 需求分析：生成结构化分析、编辑并确认关键需求；
4. PRD：根据已确认分析生成、编辑、保存和导出 Markdown。

### 6.5 项目资料

- 支持文本、Markdown、TXT、DOCX 和 PDF；
- 单文件默认上限 20 MB；
- 显示解析中、可使用、解析失败和不支持状态；
- 失败时显示原因和重试入口；
- AI 调用前展示本次使用的资料范围；
- 删除资料前确认其对分析和 PRD 的影响。

### 6.6 需求分析

分析至少包含：

- 产品目标；
- 目标用户；
- 核心场景；
- 用户痛点；
- 核心需求；
- MVP 范围；
- 待确认问题；
- 本次使用的项目资料。

分析结果标记为“AI 草稿”，允许编辑、补充、重新分析和确认。未确认时不得生成正式 PRD。

### 6.7 PRD 工作区

- 根据已确认需求生成结构化 PRD；
- 支持章节导航和正文编辑；
- 支持自动保存并显示保存状态；
- 单章节重新生成不得覆盖其他章节或手工修改；
- 生成失败或停止时保留原章节；
- V1.0 导出 Markdown，不提供 Word/PDF 导出。

### 6.8 任务中心

- 显示任务类型、所属项目、状态和操作；
- 支持等待、运行、等待确认、部分完成、完成、失败和未知状态；
- 同类主要任务重复点击时不创建重复任务；
- 失败任务提供原因和重试入口；
- 离开页面后任务继续运行，并可重新进入查看。

### 6.9 设置

模型服务：

- 接口地址；
- API Key 输入与脱敏回显；
- 模型标识；
- 连接测试；
- 默认模型；
- 已保存但不可用的模型必须标记为不可用，不能静默替换。

执行方式：

- 查看 Codex/Pi 是否可用；
- 设置默认执行方式；
- 不可用时显示原因和替代入口。

其他设置：

- 本地数据保存位置；
- 主题和语言；
- 应用版本。

## 7. 核心流程

### 7.1 从产品想法生成 PRD

```text
工作台
→ 从产品想法开始
→ 创建项目
→ 输入产品想法
→ 需求与 PRD 助手生成需求分析草稿
→ 用户编辑并回答待确认问题
→ 用户确认需求分析
→ 生成结构化 PRD
→ 编辑、保存并按需导出 Markdown
```

### 7.2 临时新建会话

```text
任意一级页面
→ 点击“新建会话”或按 Ctrl+N
→ 进入未关联项目的新会话
→ 使用全局默认助手、模型和自动执行器
→ 用户可选择关联项目
→ 关联后显示项目默认模型和可使用资料
→ 发送消息
→ 生成会话标题并进入最近对话
```

### 7.3 首次配置模型

```text
用户触发 AI 功能
→ 系统发现无可用模型
→ 保留输入和上下文
→ 引导进入模型设置
→ 填写接口地址、API Key 和模型标识
→ 测试连接并设为默认模型
→ 返回原任务
→ 用户再次发起任务
```

## 8. 状态与恢复

AI 任务可能处于：等待发送、提交中、已排队、等待响应、流式生成、等待用户确认、部分完成、完成、失败、连接中断或未知状态。

恢复规则：

- AI 失败时保留用户输入和已有内容；
- 停止流式生成时保留已生成部分并允许重新生成；
- 连接中断不等于任务取消；恢复后按任务 ID 查询 AionCore；
- 应用异常退出后恢复已保存项目、资料、确认结果和 PRD；
- 历史会话恢复消息、项目关联、助手和模型；
- 未保存内容存在风险时必须明确提示，不得显示虚假成功。

## 9. 安全与隐私

- API Key 不得写入代码、仓库、日志或导出文件；
- 界面回显 Key 时必须脱敏；
- 项目资料默认保存在本机；
- 只有用户触发模型任务时，才发送该任务所需的最小内容；
- 日志不得记录完整私密资料、完整模型输入输出或内部堆栈；
- 上传文件校验扩展名、真实内容类型、大小和安全文件名；
- 删除项目、资料或 PRD 前二次确认并说明影响范围；
- AI 生成的 Markdown、链接和文件名按不可信内容处理。

## 10. 关键验收标准

| ID | 场景 | 预期结果 |
|---|---|---|
| NAV-01 | 点击工作台 | 返回首页且工作台显示选中状态 |
| NAV-02 | 点击产品名称 | 与点击工作台效果一致，但不是唯一入口 |
| NAV-03 | 点击新建会话 | 进入未关联项目的新会话并聚焦输入区 |
| NAV-04 | 按 `Ctrl+N` | 与点击新建会话效果一致 |
| NAV-05 | 查看侧栏 | 最近项目与最近对话分组显示，不混排 |
| CHAT-01 | 新建会话且不手动配置 | 使用需求与 PRD 助手、全局默认模型和自动执行器 |
| CHAT-02 | 关联项目 | 显示项目默认模型和本次可使用的资料 |
| CHAT-03 | 恢复历史会话 | 恢复消息、项目、助手和模型，不创建重复会话 |
| AI-01 | 需求分析完成 | 结果标记为 AI 草稿，确认前不能生成正式 PRD |
| AI-02 | AI 生成失败 | 保留用户输入和已有内容，并提供重试入口 |
| TASK-01 | 重复启动同类主要任务 | 不创建重复任务并说明当前状态 |
| REC-01 | 重启应用 | 已保存项目、资料、确认结果和 PRD 可以重新打开 |
| SET-01 | 模型或执行器不可用 | 显示原因和切换入口，不静默替换 |
| SEC-01 | 重新进入设置 | API Key 脱敏显示，日志和导出中无明文 Key |

## 11. 原型交付

本版本附带独立可点击 HTML 原型：

- 文件：`docs/prototypes/product-manager-workbench-v1.1.html`
- 覆盖：工作台、新建会话、项目列表、项目工作区、资料、需求分析、PRD、任务中心和设置；
- 包含：最近项目/最近对话、助手与模型选择、更多设置、项目资料提示和历史会话恢复；
- 已验证：工作台入口、新建会话、品牌返回、`Ctrl+N`、项目关联和历史会话恢复；
- 原型用途：产品和交互验收；不得把原型通过等同于 AionUi 生产实现完成。

## 12. 后续实施边界

用户确认本设计版本后，才进入 AionUi（Electron + React）正式前端实现。实施时复用现有项目结构和组件能力，不更换既定技术路线，不在本设计提交中修改生产 UI、后端、部署或数据结构。
