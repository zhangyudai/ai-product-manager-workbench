## 三、当前界面与 PRD 的差距

本次桌面启动验证证明 AionUi/AionCore 技术基线可用，但启动后的界面仍主要是上游 AionUi 的通用对话工作台，不应视为产品经理 AI 工作台 V1.0 已完成。

当前已能看到产品品牌、三种需求提示词和“需求与 PRD 助手”，但仍缺少：

- 符合 PRD 的一级导航：新会话、项目、任务、设置；
- 工作台首页：创建项目、最近项目、最近对话和运行任务；
- 以项目为核心的三种开始方式，而不是只向聊天输入框填入提示词；
- 项目概览、项目资料、需求分析和 PRD 四个项目工作区页面；
- 需求分析后的人工修改与确认，以及确认后生成、编辑和保存 PRD 的完整主流程；
- 将助手、模型和执行器按 PRD 规定的层级展示，执行器默认收进“更多设置”；
- 从 V1.0 主入口隐藏团队、模型对比台等非本期核心能力。

### 开发与测试节奏

- 当前仓库的 `just push` 固定在每次推送前执行全仓库测试；对于只修改进度文档的提交，这个门禁明显过重，因此后续减少零碎推送，以可验收的功能里程碑为单位集中提交和推送；
- 日常功能开发只运行本次改动直接相关的测试，并补充必要的回归用例；
- 前端改动按影响范围运行类型检查、国际化检查和针对性组件测试，后端改动优先运行受影响的 Rust crate 测试；
- 一个完整功能或阶段完成后，再运行覆盖该功能链路的前后端检查；
- 全仓库测试主要用于准备合并 PR、发布安装包或阶段验收，不在每个小提交前重复执行；
- 遇到与当前改动无关的上游测试失败时，先单独复现并区分真实缺陷、环境问题和测试超时，再决定修复方式，不让无关门禁长期阻塞产品主线。
