#### 2026-10-08 验收问题与解决记录

**问题 1：页面无法直观看出不同项目是否会串用数据，也看不出数据模型、接口和恢复规则是否真正有测试覆盖。**

- 原因：这些属于底层非视觉规则，不能只靠项目卡片和空状态证明；原有测试覆盖了跨用户隔离和单次进程内的项目生命周期，但没有直接覆盖“同一用户的 A、B 两个项目隔离”，也没有模拟 SQLite 关闭后重新打开；
- 解决：新增 `folders_attached_to_one_project_do_not_appear_in_another_project`，验证只挂到项目 A 的资料根不会出现在项目 B；新增 `project_state_is_restored_after_database_reopen`，使用真实 SQLite 文件写入项目，关闭连接后重新打开并校验项目名称、项目 ID 和工作区；
- 验证：连同项目创建/列表/改名/打开/最近排序、非法名称拦截和跨用户读取隔离，共 5 项 M2 Rust 定向测试通过；
- 边界：M2 当前只实现项目结构和持久化，项目资料、需求分析与 PRD 页签尚无真实内容，因此现阶段页面只能检查不同项目入口和工作区路径，内容级不串用由自动化测试证明，待后续页签接入真实数据后再增加可视化验收。

**问题 2：本地验收链接 `http://127.0.0.1:25809/#/workbench` 打开后白屏。**

- 原因：`25809` 端口当时没有服务监听，旧预览进程已经停止，不是浏览器操作错误；首次修复虽然成功启动了服务，但服务仍附着在临时执行会话上，执行会话结束后进程再次退出，因此不属于可靠修复；
- 解决：只构建受影响的 AionCore `aioncore` 后端和 AionUi 前端产物，再通过 Windows 隐藏后台进程启动 WebUI，并把标准输出和错误日志分别写入仓库的 `.codex-runtime/webui.out.log` 与 `.codex-runtime/webui.err.log`；没有重复执行全仓库测试；
- 验证：`http://127.0.0.1:25809/#/projects` 返回 HTTP 200，项目接口返回 2 个验收样例；页面可看到分别绑定 `E:\Codex\90_临时文件\M2验收\项目A` 与 `项目B` 的两个项目，并可进入各自工作区；
- 恢复方式：若以后本地链接再次无法访问，先检查 `25809` 是否监听；在 `AionUi` 目录设置 `AIONUI_BACKEND_BIN` 指向本分支构建出的 `AionCore\target\debug\aioncore.exe`，再以 Windows 后台进程运行 `bun scripts/webui.ts --no-build --no-open`。`--no-build` 仅适用于前端产物已经刷新后的重启；该后台预览不是开机自启服务，手动结束进程或重启电脑后仍需重新启动。
